# QUBIQ 2021 Data Provenance

## Scope

This project uses the QUBIQ 2021 challenge release uploaded as three original ZIP archives. The archives are retained unchanged under `data/archives/`; all extracted files under `data/raw/` are treated as immutable source data.

- `data/raw/train/training_data_v3_QC/`
- `data/raw/valid/validation_data_qubiq2021/`
- `data/raw/test/QUBIQ21_test/`

macOS packaging artifacts (`__MACOSX`, `.DS_Store`, and `._*`) were removed after extraction. No NIfTI image or segmentation file was modified.

## Manifest

The canonical machine-readable index is:

- `data/processed/qubiq2021_manifest.csv`
- `data/processed/qubiq2021_summary.json`

It is generated by `scripts/build_qubiq_manifest.py`.

Every downstream experiment should discover data through the manifest rather than by assuming directory names or a fixed number of raters.

## Observed dataset structure

### Prostate

- Labeled cases: 48 train + 7 validation = 55.
- Test images: 13, without public annotations in the provided archive.
- Two segmentation tasks per case.
- Usually six annotations per task.
- QC exceptions in training:
  - `case09`: task01 = 5, task02 = 5.
  - `case16`: task01 = 6, task02 = 5.
  - `case31`: task01 = 6, task02 = 5.

These exceptions are consistent with the challenge QC note that three prostate subjects have only five annotations after quality control.

### Brain growth

- Labeled cases: 34 train + 5 validation = 39.
- Test images: 10.
- Seven annotations per labeled case.
- Some historical files use `caseXX_segYY.nii.gz` instead of `task01_segYY.nii.gz`; the manifest builder handles both patterns.

### Brain tumor

- Labeled cases: 28 train + 4 validation = 32.
- Test images: 8.
- Three segmentation tasks, each with three annotations per labeled case.

### Kidney

- Labeled cases: 20 train + 4 validation = 24.
- Test images: 4.
- Three annotations per labeled case.

### Pancreas

- 40 train + 18 validation + 18 test = 76 scans.
- Training cases expose two annotations for task01.
- Validation contains task01 for all cases and task02 for a subset; this must not be treated as a balanced rater/task matrix without explicit filtering.

### Pancreatic lesion

- 22 train + 10 validation + 10 test = 42 scans.
- The uploaded QC train/validation archives contain two segmentation masks per labeled scan (`task01_seg01`, `task01_seg02`).
- The challenge website description previously examined states three annotations per scan. This is a provenance discrepancy and must not be silently reconciled. Analyses using this task must explicitly state that the local QC release contains two observed annotations per labeled scan.

## Important analysis rules

1. Split by case/patient unit, never by annotation file.
2. Never allow annotations from one case to appear across training/calibration/test partitions.
3. Do not treat multiple annotations from the same case as i.i.d. observations for conformal calibration unless intentionally evaluating that naive baseline.
4. The official test ZIP contains images but no public expert masks; it cannot be used for local coverage evaluation.
5. For the pilot study, use only labeled train/validation cases and create a new case-level development/calibration/evaluation split.
6. Preserve missing-rater patterns; do not fabricate labels or silently drop incomplete cases.
7. Original archives are immutable provenance artifacts. Derived resampling, normalization, consensus masks, crops, and model inputs belong under `data/processed/` or a later derivatives directory.

## Pilot default

The initial Go/No-Go pilot will start from the QUBIQ prostate task because it provides the cleanest combination of sample size and repeated annotations. Prostate task01 and task02 will be profiled separately before choosing the first experimental target.
